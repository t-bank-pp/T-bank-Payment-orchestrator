# TBPO-12: приёмочные проверки API

Сценарии TBPO-7 v4.1: создание и чтение платежа, повтор и конфликт ключа,
нормализация строк, порядок JSON-полей, строгая валидация, границы bigint и
длины строк. Проверяются ответы API и все три таблицы через отдельное соединение:
payments, payment_attempts и outbox. При отказе или повторе сравниваются полные
снимки данных, включая идентификаторы, поля и даты.

Добавлены 80 проверок: 76 в `test_payment_creation.py` и 4 в
`test_read_boundaries.py`. Они входят в стандартный запуск pytest и существующий CI.
Рабочий код, общие фикстуры и настройки CI не изменены.

## Запуск

Из корня репозитория установить зависимости по основному README. Задать
`TEST_DATABASE_URL` для отдельной тестовой PostgreSQL 16 с правом создания баз.
Общая фикстура проекта создаёт базу на каждый случай, выполняет миграции и удаляет
только эту базу. Без переменной интеграционные тесты пропускаются — это не приёмка.

```sh
.venv/bin/pytest -q services/payment/tests/tbpo12
.venv/bin/pytest -q
```
